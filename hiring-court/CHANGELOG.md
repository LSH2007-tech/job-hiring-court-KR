# 변경 이력 (CHANGELOG)

취업재판(hiring-court) 플러그인의 판별 변경 이력입니다.
재판 규칙은 `skills/hiring-court/SKILL.md`에 있고, 이력은 재판을 열 때마다 읽히지 않도록 이 파일에만 둔다. 새 판을 낼 때는 맨 위에 항목을 더한다.

## 플러그인 1.6.6 · 재판도구 1.3.4 (2026-11-14)

- 보안 사항을 업데이트하였습니다.
- **처음 화면과 README에 이 재판의 특징을 먼저 적었다.** 공고의 직무(JD)와 지원자 스킬을 맞춰 어떤 직무가 맞는지, 그 직무에 맞춰 자소서를 어떻게 완성할지 돕는 AI라는 점을 앞에 둔다.
- **사용량 안내를 더했다.** 재판 한 번에 Claude를 10번 안팎 부르고, Pro 요금제(Opus 5.5, 높은 연산 수준)에서 5시간 사용 한도의 약 20~30%를 쓴다(2026-11-14 한 번 측정). 처음 화면, README, 소개 페이지에 알린다.
- 웹 화면 문구: 공방 단계 설명을 '탈락 위원과 합격 위원이 해당 지원자를 어떻게 판단하는지 밝히고 합불을 공방합니다'로, 추천 초안의 주의 글을 'AI가 추천해 준 예시입니다…'로 바꿨다.
- **AI 추천 초안을 더했다 (웹 화면 1단계 맨 아래).** 써 둔 자기소개서가 없을 때, 노션이나 지원자 파일로 넣은 지원자 기록의
  경험으로 서기가 문항마다 추천 예시를 쓴다. 결과부터 말하는 두괄식으로 X(문제) → Y(해결) → Z(수치 결과) 순서다.
  지원자 기록이 없으면 쓰지 않고 직접 쓰게 한다. 초안은 답변 칸에 넣어 고친 뒤 재판에 올린다.
- **초안의 글자 수를 회사가 정한 제한에 맞춘다.** 문항마다 글자 수(300~2,000자, 직접 입력, 제한 없음)를 고르면 그 95~100%로
  쓴다. 글자 수는 코드가 세고, 벗어난 문항은 한 번 다시 다듬는다. 그래도 벗어나면 '확인이 필요한 것'에 알린다.

- **공고로 충분한지는 글자 수가 아니라 내용으로 서기가 판단한다.** 공고는 직무마다 길이가 다르다. 어느 회사의 어떤 직무인지,
  하는 일, 지원 자격이 드러나면 짧아도 통과하고, 빠진 것이 있으면 화면의 '주의'에 빠진 항목을 알린다(진행을 막지 않는다).
  주요 업무가 하나도 없을 때만 재판을 열지 않는다. 최대 글자 수는 없다.
- **공고 분석에 '이 공고가 찾는 사람'을 더했다.** 인사팀과 현업이 찾는 사람의 요점 3~5개를 근거가 된 공고 문구와 함께 정리해
  화면 맨 위에 보여 주고, 사건 기록에도 넣어 공방과 배심이 같은 요점을 본다.
- **공고 분석 때 웹에서 회사와 직무를 찾아본다.** 채용 페이지의 추가 설명, 회사의 당면 과제, 현직자가 말하는 실제 업무를 찾아
  '웹에서 더 찾은 정보'로 출처와 함께 보여 준다. 공고의 업무와 자격에는 공고에 적힌 것만 쓴다.
- **글자가 뽑히지 않는 파일(스캔 PDF, 이미지)은 멈추지 않고 화면처럼 보고 읽는다.** 파일 칸에 캡처 이미지를 넣어도 된다.
- 글자 수 기준(재판도구 1.3.4, 30자)은 "글자를 거의 못 읽었다"만 가린다. 파일, 캡처, 붙여넣기 모두 같은 기준이다.
- 글자를 못 읽었을 때 "스캔본일 수 있어요" 대신 실제로 읽은 글자 수를 알려 준다.
- 웹 화면: HTML 공고에서 뺀 숨은 글의 개수를 '숨은 문장 정리' 줄에 보여 준다.

## 플러그인 1.6.5 · 재판도구 1.3.3 (2026-11-13)

- **공고 정리(`guard`, `extract`)의 HTML 읽기를 고쳤다.** 화면에 보이지 않는 글을 더 정확히 가려내고, 보이는 본문이 숨은 글로
  잘못 분류되어 빠지던 문제(배경색, 테두리 두께 같은 스타일, 닫는 태그가 없는 `<p>`와 `<li>`)를 고쳤다. 숨은 글은 버리지 않고
  보고에 남긴다.
- 설명 문서를 한국어와 영어 두 가지로 나눴다(`README.md`, `README.ko.md`, `hiring-court/README.md`, `hiring-court/README.en.md`).
- 버전 표기가 파일마다 같은지 테스트가 확인한다. `publish/export.sh`는 내보낸 결과물에서도 테스트를 돌린다.

## 플러그인 1.6.4 (2026-11-13)

배포 안정성: 올린 판이 올린 그대로 돌게 했다.

- **브라우저 앱이 재판 규칙을 실행 중에 `main` 브랜치에서 받아 오지 않는다.** 규칙을 앱과 함께 `docs/app/skill.json`으로 넣는다.
  규칙과 엔진이 언제나 같은 커밋의 것이고, 규칙 문서를 고쳐도 배포된 앱이 갑자기 깨지지 않는다.
- **Anthropic SDK를 CDN에서 받지 않고 저장소에 넣었다**(`web/static/vendor/`, 파일 해시를 테스트가 확인한다).
  JSZip은 고정 버전에 무결성 해시(SRI)를 붙였다.
- `publish/export.sh`는 커밋하지 않은 변경이 있거나 테스트가 하나라도 실패하면 내보내지 않는다.
- CI의 GitHub Actions를 커밋 해시로 고정했다. 공개 저장소에 판마다 태그를 붙인다.
- `SKILL.md`나 `web/`을 고친 뒤에는 `python hiring-court/web/build_browser.py`를 다시 돌린다(안 돌리면 테스트가 알려 준다).

## 플러그인 1.6.3 · 스킬 V15.2 · 재판도구 1.3.2 (2026-11-13)

- **고침: HTML 공고를 `guard`에 넣으면 `AttributeError`로 죽던 문제.** `court_tool.py`에 `_Visible` 클래스가 두 번 정의되어
  뒤의 것(`extract`용)이 앞의 것(`guard`용)을 덮어썼다. 그래서 HTML 입력에서는 숨은 글(흰 글씨, 크기 0, `display:none`) 제거가
  한 번도 동작하지 않았다. 클래스를 하나로 합쳤고, HTML 입력 테스트를 더했다.
- **`extract`도 HTML의 숨은 요소를 뽑지 않는다.** 웹 화면에 HTML 파일로 넣은 공고는 `extract`를 먼저 거치므로, 숨은 글이
  본문에 섞여 들어가던 길을 막았다. 뺀 개수는 보고의 `숨은 요소 제외`에 나온다.
- 보안 사항을 업데이트하였습니다.
- **SKILL.md에서 변경 이력을 이 파일로 옮겼다**(재판마다 읽히는 글을 줄인다).

## 그 전

- 글 완성도를 0순위로 두던 판에서 **JD 맞춤(직무 일치)을 0순위**로 바꿨다. 실제 결과와 예측을 대조한 오판 분석에서, 직무 일치가 높은
  서류는 글에 약점이 있어도 붙고 낮은 서류는 글이 다듬어져 있어도 떨어지는 일이 반복되었기 때문이다.
- 기준 구간(높음 45~80%, 중간 20~50%, 낮음 5~25%)은 2026-10-22에 확정한 가설값이다.
