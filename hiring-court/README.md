# 취업 재판 (hiring-court)

자기소개서를 **모의 재판**에 올려, 여러 AI가 찬반 공방과 독립 투표를 거쳐 **서류 합격 가능성을 예측하고 고칠 점을 판결**하는 Claude 스킬입니다.

> AI 한 명이 평가하면 결국 듣기 좋은 방향으로 수렴합니다. 역할을 나누고, 서로의 표를 볼 수 없게 해서 그 쏠림을 줄이는 것이 핵심입니다.

## 설치 (Claude Code)

```
/plugin install hiring-court --marketplace LSH2007-tech/job-hiring-court-KR
```

또는 두 단계로:

```
/plugin marketplace add LSH2007-tech/job-hiring-court-KR
/plugin install hiring-court@lsh-skills
```

## 재판부 구성

| 역할 | 하는 일 |
|---|---|
| **검사** | 탈락시킬 이유를 찾아 공격 |
| **변호인** | 붙여야 할 이유로 방어 |
| **배심원 3명** | 인사담당자(Sonnet), 임원진(Opus), 실무 담당자(Sonnet)가 서로의 표를 모른 채 각자 투표 |
| **판사(서기)** | 표결을 정리해 판결하고, 첨삭이나 면접 준비 자료를 작성 |
| **경쟁자 비교 참조인** (선택) | 전형적 경쟁 지원자와 비교해 "단독 %"와 "경쟁 풀 %"를 냄. 표결에는 들어가지 않음 |

임원진과 실무 담당자의 관점은 **웹에서 찾은 현직자 자료**(조직장 인터뷰, 기술 발표, 현직자 후기, 회사 동향)로 세우고, 출처를 기록에 남깁니다.

## 진행 순서

0. **입력 정리**: 노션 또는 증거자료 파일(이력서, 경력기술서, 기존 자소서)에서 경력·경험 데이터를 가져오고, 공고 대상(신입/경력 등)을 확인하고, **직무 일치표**를 작성
1. **사건 기록**: 회사, 공고 원문, 자소서, 경력 요약을 한곳에 정리
2. **공방**: 검사·변호인 모두진술(최대 800자) → 반박(최대 400자) → 핵심 쟁점
3. **배심 표결**: 배심원 3명이 동시에 독립적으로 투표
4. **판결**: 합격 / 탈락 / 보류(경계) + 서류 합격 예측 %
5. **결과물**: 제출 전이면 **첨삭 수정본**, 제출 후면 **면접 예상 질문과 답변 준비**

### 모드

- **서류 재판 (제출 전)**: 판결 → 첨삭 수정본
- **면접 대비 재판 (제출 후)**: 판결 → 면접 답변 준비 (제출본은 고치지 않음)

## 평가 기준

- **0순위: JD 맞춤**. "이 회사가 찾는 사람인가"를 먼저 봅니다. 글 완성도를 먼저 보던 이전 판이 실제 결과와 반대로 예측한 사례가 쌓여 이 순서로 바꿨습니다.
- **1순위: 스토리텔링**. 하루 수백 장을 읽는 심사자에게 읽히는지 봅니다. 첫 문장, 장면, 긴장, 수치로 보이는 변화가 있는지 확인합니다.
- 그다음: 포지셔닝, 구조(두괄식·소제목), STAR 뼈대, 사실과 출처, 문체와 분량

### 판결 규칙

- 서류 예측 % = **인사 + 실무 배심원의 평균** (임원 점수는 "임원 시선"으로 따로 적고 예측에 넣지 않음)
- **55% 이상 합격**, **45% 이하 탈락**, 그 사이는 **보류(경계)**
- 면접 예측은 배심원 3명 평균, 면접 판정은 3명 다수결

## 계산 도구: `scripts/court_tool.py`

**판단은 모델이, 세는 것은 코드가** 맡습니다. 숫자 계산과 형식 검사는 모두 이 도구로 합니다.

| 명령 | 기능 |
|---|---|
| `guard` | 공고문 정리 (숨긴 텍스트, 프롬프트 주입 문구 제거) |
| `count` | 글자 수 / 단어 수 |
| `match` | 직무 일치도(높음/중간/낮음)와 기준 구간 |
| `check` / `tally` | 배심 파일 형식 검사와 집계 |
| `row` | 예측 기록 한 줄 생성 |
| `brier` | 실제 결과와 비교한 정확도(Brier 점수) |

직무 일치도별 기준 구간: **높음 45~80% · 중간 20~50% · 낮음 5~25%**

## 사용량

하위 에이전트는 기본 **4회**(공방 1 + 배심원 3)만 씁니다. 재실행 규칙에 걸리면 최대 7~8회까지 늘고, 참조인을 더하면 1명당 1회씩 늘어납니다(경쟁자 비교 참조인을 두면 기본 5회).

## 기록 저장소 (노션)

재판부, 예측기록, 오판분석, 회사별 참고자료와 면접대비는 노션의 `서류재판 기록` 페이지에 저장합니다. claude.ai와 Claude Code 어느 쪽에서 재판을 열어도 같은 기록을 이어 씁니다. 노션에 쓸 수 없으면 claude.ai 프로젝트 문서나 작업 폴더에 저장합니다.

## 도구 종료 코드

`0` 정상 · `1` 검사에 걸림(형식 오류, 주의 필요) · `2` 입력 문제(파일, 옵션) · `3` 도구 내부 오류. 오류는 Traceback 대신 한 줄 메시지로 나옵니다.

- 파일 글자 뽑기(권장): `python -m pip install "markitdown[pdf,docx,pptx,xlsx]"`. PDF, Word, PowerPoint, Excel을 제목과 표 구조가 살아 있는 마크다운으로 바꾼다. 설치하지 않으면 PDF는 `pypdf`(`python -m pip install pypdf`), Word와 hwpx는 내장 파서로 대신한다. PowerPoint와 Excel은 markitdown이 있어야 읽는다.

## 웹 화면 (v1.6.5)

`취업재판-시작` 스킬이 이 PC에서 로컬 웹 화면을 띄운다(Claude Code에 "취업 재판 시작"이라고 말한다)(`web/server.py`, 주소는 서버가 켜질 때 알려 준다: `http://localhost:8765/?k=<열쇠>`). 공고 접수부터 판결, 조언, 기록 저장까지 화면에서 단계별로 진행한다. Claude Code 밖에서 바로 열려면 `web/run.bat`을 실행한다.

- 판단은 이 PC에 로그인된 Claude Code(`claude -p`)가 하므로 사용자의 구독에서 돈다. 운영 서버나 API 키가 없다.
- 지원자 기록: 증거자료 파일(이력서, 경력기술서, 기존 자소서) 또는 노션(읽기 전용). 노션은 Claude Code에 `notion` 이름으로 등록하고 한 번 로그인해야 한다.
- 공고는 캡처 이미지, 파일(PDF, Word, hwpx), 본문 붙여넣기로 받는다. 링크는 받지 않는다(채용 사이트 대부분이 링크만으로는 본문을 주지 않는다). 공고 페이지에서 Ctrl+P → 'PDF로 저장'으로 만든 파일을 넣으면 된다.
- 단계마다 Claude가 지금 하는 일(읽는 파일, 쓰는 파일)과 지난 시간을 화면에 보인다.
- v1.6.3에서 보안 사항을 업데이트하였습니다.
- 사용자 자료는 플러그인 폴더 밖(`~/.hiring-court/`, 저장 폴더 기본 `문서/취업재판`)에 둔다.
